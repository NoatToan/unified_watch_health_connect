## 1. Connection lifecycle end-to-end

1. **Scan / recognise** — Garmin Connect reads manufacturer data company id 135 (`0x0087`) or byte-swapped 34560 (`0x8700`); the first two bytes big-endian are the product number (`SRC/dk2/d.java:386-396`) [V]. Device names and Garmin service-data UUIDs supplement recognition (`SRC/ik2/c.java`; protocol doc §2.1) [V]. Reconnect scanning filters by MAC address and uses a `PendingIntent` broadcast on API ≥37 (`SRC/pj2/v.java:523-556`) [V]. Scan timeout: 90 s when phone uptime <120 s, else 300 s (`j8=90000`, `f138116w=300000`, `SRC/pj2/v.java:496,529-556`) [V]. Our driver only scores advertisements (company ids, `6A4E…` family, name regex) in `DRV/GarminDriver.kt:26-37`; scanning itself is core-owned [V].

2. **Choose transport** — Vendor builds the candidate UUID set: a dedicated GFDI UUID from config (`9B012401`/`6A4E2401` for `CONNECT_MOBILE`), else Multi-Link `6A4E2800`; no subscriber ⇒ fail `BLE_NO_SERVICE_SUBSCRIBER` (`SRC/ma2/a.java:330-407`, `SRC/com/garmin/android/gfdi/configuration/GdiClientConfigurationUtil.java:166-183`, `SRC/ma2/h.java:62-85`) [V]. The `dedicated_gfdi_service=CONNECT_MOBILE` asset maps to both legacy and current GFDI services (asset line 6) [V]. Driver order matches: `6A4E2401` (`CD28`/`4C80`) → `9B012401` (`4ACBCD28`/`DF334C80`) → Multi-Link (`DRV/transport/GfdiStream.kt:32-55`, `DRV/GarminUuids.kt`) [V].

3. **connectGatt** — `connectGatt(context, autoConnect=!direct, callback, TRANSPORT_LE)` (`SRC/pj2/v.java:565-596`) [V]. Timeout 30 s for a direct connect, 90 s for auto-connect (`SRC/pj2/v.java:582`) [V]; an overall 120 s `Timer` aborts the attempt (`SRC/pj2/v.java:584`) [V]. Callback state machine: `NOT_STARTED→SCANNING→CONNECTING_GATT→WAITING_FOR_BOND→DISCOVERING_SERVICES→AVAILABLE→DISCONNECTING→FINISHED` (`SRC/pj2/v.java:1315-1331`); service discovery has a 15 s timeout (`SRC/pj2/v.java:598-605`) [V]. Driver delegates connect/bond to core via `LinkRequirements(bond=true, mtu=515)` (`DRV/GarminDriver.kt:23-24`) [V].

4. **OS bond** — Bonding is requested only for *pairing* connections: `ma2.a.d(..., z14=true, PAIRING, ...)` vs `z14=false` for persistent/probe (`SRC/la2/e.java:640,852`; probe `:577`) [V]. `onConnectionStateChange` routes to `WAITING_FOR_BOND` unless already `BONDED`, so bond precedes service discovery (`SRC/pj2/v.java:1237-1245`) [V]. `createBond()` has a 45 s timeout, and `ACTION_BOND_STATE_CHANGED`/`ENCRYPTION_CHANGE` receivers advance the state (`SRC/pj2/v.java:515-521,1379-1414`) [V]. Driver requires bond before opening the session (`DRV/GarminDriver.kt:24`) [V].

5. **MTU** — `requestMtu(515)` (`SRC/pj2/g.java:18`) is issued *after* services are available, and only when the per-connection flag is set: true when config has no dedicated GFDI service (Multi-Link-only device) or the MAC is in the MTU preference set (`SRC/ma2/a.java:669-706`, `SRC/pj2/t.java:21-31`) [V]. Wait 30 s (5 s on API ≥34), with duplicate-request detection (`SRC/pj2/h.java:32-46`) [V]. Failure is non-fatal (`SRC/pj2/u.java:19-27`) [V]. Driver always asks for 515 (`DRV/GarminDriver.kt:24,50`) [V].

6. **Multi-Link register** — Vendor enables notifications on one of ten `6A4E281x` characteristics, chosen at random (`SRC/eh2/f.java:281-295`; driver picks the first, `DRV/transport/MultiLink.kt:63-71`) [V]. It sends `CLOSE_ALL` and waits 5 s (`SRC/nl2/d.java:171-180`; driver 5 s, `DRV/transport/MultiLink.kt:133-134`) [V]. It always performs the REGISTRATION/info-page query before opening any service — through service 4 when the watch exposes it, otherwise through the legacy ML info characteristic — and queries six info pages (`SRC/eh2/f.java:251-358`) [V]. Info-page query (`ml2.h0.a/c`): 1 s timeout per page, 5 retries, 20 s overall (`SRC/ml2/h0.java:101-140`) [V]. Then `REGISTER` service 1 (GFDI) via `nl2.d.f` with flags 2 only when MLR is available, otherwise 0; `PENDING_AUTH (2)` is waited through for up to 30 s (`SRC/nl2/d.java:211-236`, `SRC/nl2/h.java:39-92`) [V]. Status 3 (ALREADY_IN_USE) carries an alternative service UUID (`6A4E%04X`) that the driver ignores (`SRC/nl2/h.java:53-64`) [V]. Driver goes straight to `REGISTER(1, flags=0)` and only runs the service-4 sequence after `REJECTED`, then retries once (`DRV/transport/MultiLink.kt:73-128`) [V]. REGISTER-RESP layout is `00 01 | clientId u64 | serviceId u16 | status | handle | reliableFlags | version` (`SRC/nl2/h.java:44-72`; driver `DRV/codec/MultiLinkCodec.kt:84-100`) [V].

7. **GFDI handshake** — Watch sends 5024 (`at2.a.onMessageReceived`): `protocolVersion u16 | productNumber u16 | unitId u32 | softwareVersion u16 | maxPacketSize u16 | string8×3`, optional dual-BT MACs (`SRC/at2/a.java:472-540`) [V]. Host replies with protocol 113 (or 150 when device ≥150 and the compact-header feature is on), product/unit `0xFFFF…`, app version, friendly name, manufacturer, model, `0x01` (`SRC/at2/a.java:350-376`) [V]; driver always announces 113 and uses the non-compact header (`DRV/codec/GfdiPayloads.kt:68-91`) [V]. Watch then sends 5050 configuration; host ACKs and sends its own capability bitmask built from the union of its handlers (`SRC/at2/a.java:429-458`, `SRC/rs2/a.java:39-55`) [V]; driver sends a fixed set `{0,3,4,5,29,71}` (`DRV/codec/GfdiPayloads.kt:134-155`) [V]. FIT capability messages 5011/5012 are answered (`SRC/at2/a.java:283-342`) [V], then protobuf 5043 `FeatureCapabilitiesRequest/Response` is exchanged (`SRC/rs2/i.java:186-231`) [V]. The app marks the handshake complete after FIT capabilities (`SRC/at2/a.java:219-231`) and sends 5030 `HANDSHAKE_COMPLETE (8)` through its session layer (`SRC/vs2/l.java:96-100`) [V]. A per-MAC 30 s handshake watchdog fires `HANDSHAKE_TIMEOUT` if completion never arrives (`SRC/da2/h.java:128`, `SRC/la2/e.java:215-233`) [V].

8. **Optional Garmin Auth** — At GFDI session creation the app picks the real `AuthHandler` when `isGarminAuthAllowed` (phone not bonded, or manufacturer `VIVO`), else a stub that rejects any 5101 (`SRC/rs2/i.java:858-867`) [V]; predicate in `SRC/com/garmin/android/gfdi/DefaultAuthDelegate.java:45-59` [V]. Auth runs in parallel with the handshake (`SRC/rs2/i.java:856-882`) [V]. Call points: messages 5101/5103/5107/5108/5109/5111/5112 (`SRC/ss2/c.java:152-158`); passkey modes 0=visible (device-supplied seconds, default 30), 1=just-works (16 zero bytes), 2=OOB, each with a 30 s wait (`SRC/ss2/c.java:692-738,127-150`) [V]. LTK/EDIV/random and passkey handlers live per MAC in `AuthRegistry` (`SRC/com/garmin/android/gfdi/AuthRegistry.java:16-188`) [V]. Deeper crypto: `garmin-analysis/AUTH_CRYPTO_ANALYSIS.md`.

9. **Pairing state machine** — States: `AUTHENTICATING…CONNECTING_SUCCESS → RETRIEVING_GARMIN_DEVICE_XML → REGISTERING_DEVICE → COMPLETE` (`SRC/qm2/k.java:3-50`) [V]. `PAIR_START (5030/3)` is sent once the handshake is fully complete (`SRC/qm2/b.java:298-316`) [V]. `GarminDevice.xml` is downloaded with a 30 s timer and one retry (`SRC/qm2/b.java:328-337`, `SRC/sm2/w.java:121-130`) [V]. Cloud `registerDevice()` runs next and, on success, `PAIR_COMPLETE (5030/4)` is sent (`SRC/qm2/e.java:48-57`, `SRC/qm2/f.java:30-78`) [V]; failures are classified `HTTP_CONFLICT_409`, `INVALID_UNIT_ID`, `NETWORK`, etc. (`SRC/yl2/e.java:4-24`) [V]. Then `completeHandshake()` sends `HANDSHAKE_COMPLETE (8)` or starts a legacy sync, and the first sync begins (`SRC/mm2/a.java:96-125`, `SRC/qm2/f.java:72-78`) [V]. Driver implements no pairing milestones, no XML download, no cloud registration; it sends `HANDSHAKE_COMPLETE` at the end of its own handshake and `SYNC_COMPLETE` after a local FIT sync (`DRV/GarminSession.kt:96,165-168,181-189`) [V/I — deliberate scope].

## 2. Context holding / session state

- **Per-device profile** — `DeviceProfile` persists: unitId, productNumber, deviceName, softwareVersion, MAC, connectionType, configurationFlags, dual-pairing MAC, `supportsMultiLink`, `bluetoothLimitation` (`SRC/com/garmin/device/pairing/impl/gdi/reconnection/AbstractDeviceConnectionWorker.java:67-76`) [V]. It is serialised into WorkManager input by `DEVICE_KEY` JSON [V].
- **Per-GFDI-session object** — `us2.f` holds connectionId(MAC), unitId, productNumber, deviceName, softwareVersion, dual-BT flag, bluetoothLimitation, configurationFlags, BLE/BTC MACs, originalConfiguration, usesFitForConfiguration, queuedDownloadPayload and **protocolVersion** (`SRC/us2/f.java:9-115`) [V]. This is the closest analogue to a "GarminSession state" object.
- **Runtime link state** — Dispatcher keeps: protocol/max-message size (`f172469l`), computed max payload (`f172470m`), encryption-enabled flag (`f172468k`), per-message-type listener map, outgoing strategy object and an `ENDED` state (`SRC/us2/b.java:55-64,153-176,221-235`) [V]. `us2.b.g()` toggles the XXTEA encryptor/decryptor after auth (`SRC/us2/b.java:245-255`) [V]. Transaction ids cycle 0…31 when compact headers are used (`SRC/us2/k.java:129-137`) [V].
- **BluetoothGatt ownership** — `pj2.b` owns a single `AtomicReference<BluetoothGatt>` and serialises every GATT call on one single-thread executor; `close()` fails pending futures and shuts the executor down (`SRC/pj2/b.java:64-67,373,838-866`) [V]. `pj2.j` wraps this in a per-MAC connection state machine `NOT_STARTED/CONNECTING/CONNECTED/TERMINATED` and holds the `SingleShotConnection` (`SRC/pj2/j.java:291-296,341-370,404-411`) [V].
- **Connection registry** — `ma2.a` keeps `HashMap<MAC, c>`; each `c` binds `pj2.j`, type `PERSISTENT/PAIRING/PROBE`, config and listener (`SRC/ma2/a.java:52,669-706`, `SRC/ma2/i.java:7-11`) [V]. A connection can be upgraded/downgraded between pairing and persistent; a config change forces disconnect/reconnect (`SRC/ma2/a.java:483-566`) [V]. Only one GATT connection per MAC exists [V].
- **clientId & ML handles** — clientId is a required non-zero u64 from `client_config.xml` (`<client_uuid>0x01</client_uuid>` in the shipped asset; `SRC/da2/e.java:40-64`) [V]. Handles are keyed `(serviceId << 16) | handle` in a `SparseArray` (`SRC/nl2/d.java:48,86-88`) [V]; the ML communicator maps both `handle→channel` and `serviceId→channel` and buffers packets for a handle re-registered within 3 s (`SRC/ml2/l.java:107-137`) [V].
- **Capability bitmask / maxPacket** — Device 5050 bits are stored as two sets (`configurationFlags`, `originalConfiguration`) in `us2.f` and persisted in `DeviceProfile` (above) [V]. `maxPacketSize` from 5024 is not used verbatim: `us2.b.e(int)` converts it to a usable payload by subtracting COBS overhead `ceil(n/254)`, then 8 bytes (or 18 rounded down to a multiple of 4 when encrypted) (`SRC/us2/b.java:221-235`) [V].
- **unitId** — 5024 `u32` unit id, carried in `us2.f` and `DeviceProfile`, used for cloud registration and broadcast extras (`SRC/at2/a.java:475-478,550`; `SRC/com/garmin/device/pairing/impl/gdi/reconnection/AbstractDeviceConnectionWorker.java:67-68`) [V].
- **LTK / AuthRegistry** — process-singleton `ConcurrentHashMap<MAC, da2.a>` with LTK, encrypted diversifier (EDIV) and random number, plus OOB passkeys and passkey handlers (`SRC/com/garmin/android/gfdi/AuthRegistry.java:16-188`) [V]. No persistence is visible in this class; entries are re-registered per process [I — persistence could live in another module, not found].
- **Reconnect / backoff** — Auto-reconnect is enabled only for `PERSISTENT` connections (`SRC/ma2/a.java:669-706`, `SRC/pj2/j.java:92-107`) [V]. `doConnect` skips scanning when the ACL is already up, and **skips direct connect** when the device is bonded but not connected (scan-first path) (`SRC/pj2/j.java:386-404`) [V]. Reconnect starts are throttled in `la2.e.m`: minimum 350 ms between connection starts, and at most 2 starts inside 700 ms (`SRC/la2/e.java:830-852`) [V]. No exponential backoff was found [I; absence of evidence].
- **CompanionDeviceManager** — association request uses a single-device `BluetoothDeviceFilter` and the `COMPANION_DEVICE_WATCH` profile on API ≥31 (`SRC/lu2/a.java:38-68`) [V]. `GCMCompanionDeviceService` receives `onDevicePresenceEvent` events 0/1, resolves the association and logs/looks up the device; no connect call is made there, and legacy callbacks are skipped on API ≥36 (`SRC/com/garmin/android/apps/connectmobile/device/companion/data/GCMCompanionDeviceService.java:114-180`) [V]. The protocol-doc claim "reconnect via CDM" is therefore only partly true: CDM presence is used, but the actual reconnect is the PERSISTENT auto-reconnect/broadcast/WorkManager path [I].
- **Foreground-service ownership** — There is **no** BLE foreground service. `GarminDeviceWakefulService` is a WorkManager `Worker`, not a Service (`SRC/com/garmin/android/apps/connectmobile/devices/GarminDeviceWakefulService.java:22-31`) [V]; `DeviceSyncService` is a plain `Service` without `startForeground` (`SRC/com/garmin/android/lib/connectdevicesync/DeviceSyncService.java:36,137`) [V]. Work is enqueued as **unique work per MAC** with `REPLACE` policy (`SRC/com/garmin/device/pairing/impl/gdi/reconnection/AbstractDeviceConnectionWorker.java:54-83`) [V].
- **Concurrency / multi-device** — `client_config.xml` declares `max_connections=5` and `service_bit_mask=0x02` (asset) [V], but no parser/enforcement of `max_connections` was found in jadx [I]. Observed limits: one connection object per MAC, the 2-in-700 ms start throttle, and explicit rejection of connections to non-paired devices (`SRC/la2/e.java:795-800`) [V]. Driver keeps only per-session coroutine/stream state, one session per `GattClient`, and relies on core for link ownership (`DRV/GarminSession.kt:56-77,191-215`) [V]; it has no per-MAC registry, bond tracking, or reconnect policy [V].

## 3. Basic operations after connect

- **Time sync** — If device 5050 flags contain bit 71, the vendor sends 5030 `TIME_UPDATED` (`vs2.k` id 16) and waits **5 s** for the watch's 5052 request (`o53.j2` = `withTimeout(5000)`), otherwise it proactively sends 5026 in `vs2.a.b` (`SRC/vs2/a.java:206-302`) [V]. On 5052 it ACKs `request[0..3] | u32 now (FIT epoch) | s32 tz offset | u32 nextDstStart | u32 nextDstEnd` (`SRC/vs2/a.java:333-347`) [V]. The 5026 form is a TLV: tag 1 time, 2 DST offset, 3 tz offset, 4/5 transitions; `UNKNOWN_OR_NOT_SUPPORTED` is tolerated (`SRC/vs2/a.java:237-312`) [V]. Driver implements only the 5052 reply (`DRV/GarminSession.kt:118-119`, `DRV/codec/GfdiPayloads.kt:94-113`) [V]; it has no 5030 `TIME_UPDATED` trigger, no 5 s wait, and no 5026 path (`rg 5026` in `DRV` finds nothing) [V].
- **Battery** — Vendor 5023 notification in `ha2.a.onMessageReceived`: length ≥6; `payload[0] & 0x70` = status (0x10 new, 0x20 good, 0x30 ok, 0x40 low, 0x50 critical, 0x70 invalid); `payload[2]` = capacity percent (`SRC/ha2/a.java:161-198`) [V for mask/offset, I for label mapping]. The handler also **polls every 10 min** in `ha2.a.start` (`scheduleAtFixedRate(..., 0, 600000)`, `SRC/ha2/a.java:201-215`) with request `FF 00 <level> FF FF FF` (`SRC/ha2/b.java:59-77`) [V]. Driver uses SIG `0x180F` as primary and 5023 as fallback (`DRV/GarminSession.kt:170-179`) [V], but its provisional layout is `[0]=percent, [1]=status` — inconsistent with the vendor parser (`DRV/codec/GfdiPayloads.kt:191-216`) [V vs V]. No polling or status mask in the driver [V].
- **Device info** — 5024 is device-initiated (`SRC/at2/a.java:472-587`); fields are kept in `us2.f`/`DeviceProfile` [V]. Driver decodes 5024 into `GarminDeviceInformation` and exposes model/FW/unitId (`DRV/GarminSession.kt:100-104,170-179`; `DRV/codec/GfdiPayloads.kt:22-57`) [V]. No SIG DIS fallback, but 5024 is mandatory before the driver's handshake completes [V].
- **Live HR** — Vendor prefers dedicated service `6A4E2500` / characteristic `6A4E2501` notifications; otherwise Multi-Link service **6** (`HEART_RATE`) (`SRC/zm2/a.java:12-15,99-166`, `SRC/xm2/h.java:11`, `SRC/eh2/d.java`) [V], with standard HRS `0x2A37` as the last resort [I/Ext]. Other realtime streams exist on 2502–250D (steps, calories, stress, SpO2, body battery…) (`SRC/zm2/a.java:12-160`) [V]. Driver uses the same order 2501 → ML service 6 → `0x2A37`; ML registration uses plain flags and closes the handle on stop (`DRV/GarminLiveHeartRate.kt:62-99,183-193`) [V]. All other realtime streams are missing in the driver [V].
- **Sync trigger / protocol handlers** — Vendor handles inbound 5037 sync request (`option u8 | len u8 | bitmask`), ACKs it and starts a sync; it also registers 5009 File Ready and 5027 Queued Download (`SRC/vs2/i.java:257-294,313-315`) [V]. Driver ACKs 5037/5011/5012 with empty data but does not start a sync; 5009/5027/5043 fall through to `UNKNOWN_OR_NOT_SUPPORTED` (`DRV/GarminSession.kt:130-147`, `DRV/codec/GfdiMessage.kt:79-95`) [V]. Driver sync is app-initiated via directory file index 0 and 5002/5004 (`DRV/GarminFileSync.kt:52-133`) [V].

## 4. Robustness behaviors worth copying

- **Timeout budget (vendor)** — scan 90 s/300 s (`SRC/pj2/v.java:496-556`); GATT 30 s direct / 90 s auto (`:582`); whole attempt 120 s (`:584`); bond 45 s (`:519`); discovery 15 s (`:602`); MTU wait 30 s/5 s (`SRC/pj2/h.java:42`); ML CLOSE_ALL 5 s (`SRC/nl2/d.java:179`); ML REGISTER 30 s incl. PENDING_AUTH (`:232`); info page 1 s ×5 + 20 s overall (`SRC/ml2/h0.java:101-140`); handshake 30 s (`SRC/da2/h.java:128`); auth passkey 30 s (`SRC/ss2/c.java:150,718,735`); GFDI request 5 s with 2 retries (`SRC/rs2/e.java:17-27`, `SRC/us2/j.java:69`); protobuf response 45 s (`SRC/us2/j.java:91-93`); GarminDevice.xml 30 s + 1 retry (`SRC/sm2/w.java:121-130`) [V].
- **Driver timeout budget** — 20 s device-info, 5 s configuration, 10 s request, 15 s inter-file silence (`DRV/GarminSession.kt:199-204`, `DRV/GarminFileSync.kt:135-140`); ML GFDI register 30 s, CLOSE_HANDLE 2 s (`DRV/transport/MultiLink.kt:136-137,213-215`); live-HR ML register 10 s (`DRV/GarminLiveHeartRate.kt:96-97`) [V]. Notably no retry of a timed-out GFDI request (vendor retries twice) [V].
- **MTU strategy** — request only when needed (Multi-Link/no dedicated service or per-MAC preference), dedupe concurrent requests, store `mtu-3` as max write length, never fail the session on MTU failure (`SRC/ma2/a.java:669-706`, `SRC/pj2/h.java:32-46`, `SRC/pj2/b.java:731-770`, `SRC/pj2/u.java:19-27`) [V]. Driver asks unconditionally; core should treat failure as non-fatal [I].
- **Write queue / flow control** — every GATT read/write/descriptor op runs on one single-thread executor, so callbacks and writes cannot interleave (`SRC/pj2/b.java:373,464-481`) [V]; each `writeCharacteristic` is retried up to 5 times with 50 ms sleeps in `pj2.b.x` and a per-connection attempt counter capped at 100 (`SRC/pj2/b.java:380-443`) [V for constants, I for exact loop due to JADX inversion]. ML control exchanges are serialised per channel (`SRC/ml2/l.java`; driver `Mutex` in `DRV/transport/MultiLink.kt:149-217`) [V]. GFDI allows several outstanding requests, one waiter per message type plus transaction ids (`SRC/us2/b.java:205-219`, `SRC/us2/k.java:129-151`) [V]; driver serialises all requests (`DRV/transport/GfdiDispatcher.kt:79-97`) [V].
- **Frame-size accounting** — vendor computes the GFDI payload limit from device `maxPacketSize` by subtracting COBS chunk overhead and 8/18 bytes of framing/encryption (`SRC/us2/b.java:221-235`) [V]; driver compares the *encoded* frame directly to `maxPacketSize` (`DRV/transport/GfdiDispatcher.kt:91-97`) [V]. The driver can therefore overrun the watch's real limit; copy the vendor math [I].
- **Bond-miss recovery** — watch `KEY_MISSING`, `ENCRYPTION_CHANGE` false, or `BOND_BONDED→BOND_NONE` in `pj2.j.a.onReceive` disables auto-reconnect, terminates the connection and reports `SYSTEM_BONDING_LOST` (`SRC/pj2/j.java:92-107,136-192`; `SRC/la2/i.java:4-27`) [V]. Re-pair uses reflection `removeBond()` + `createBond()` (`SRC/qm2/g.java:24-34`) [V]. If not bonded, the app-level 5101 path is allowed instead (`SRC/com/garmin/android/gfdi/DefaultAuthDelegate.java:45-59`) [V]. Driver does not monitor bond loss and fails on 5101 (`DRV/GarminSession.kt:135-143`) [V].
- **Error taxonomy** — low-level connection failures: 19 values incl. `CONNECT_GATT_TIMEOUT`, `CREATE_BOND_TIMEOUT`, `PREMATURE_DISCONNECT`, `REQUEST_MTU_FAILURE` (`SRC/pj2/v.java:157-177`) [V]; GDI-level: 23 values incl. `BLE_TOO_MANY_RECONNECTING_FAILURES`, `SYSTEM_BONDING_LOST`, `HANDSHAKE_TIMEOUT` (`SRC/la2/i.java`) [V]; pairing/cloud: `HTTP_CONFLICT_409`, `INVALID_UNIT_ID`, `PASSKEY_TIMEOUT` (`SRC/yl2/e.java`) [V]; GFDI ACK status 0-5 (`SRC/ct2/e.java`; driver `DRV/codec/GfdiMessage.kt:97-114`) [V]. The enum `BLE_TOO_MANY_RECONNECTING_FAILURES` exists but its emission site was not found [I].
- **Other worth-copying details** — 5024 is accepted at most twice on API ≥34, then aborts with "device repeatedly sends 5024, possible LENGTH_ERROR mismatch" (`SRC/at2/a.java:465-470`) [V]; early ML packets for a handle re-registered within 3 s are buffered and replayed (`SRC/ml2/l.java:113-123`) [V]; the device's 5050 is ACKed before the host 5050 is sent, preserving order (`SRC/at2/a.java:441-457`; driver's `afterAck`, `DRV/GarminSession.kt:105-117`) [V]; every unsolicited message is ACKed or answered `UNKNOWN_OR_NOT_SUPPORTED` so the watch does not retry into a disconnect (`DRV/transport/GfdiDispatcher.kt:39-47,124-154`) [V].
